# dev35 固定钻头三样本研究

## 结论：停止，不继续调参

钻头在同一迎石路径与反馈控制器下确有作用：实际切掉上方浮石 97.670150 HP，并使其归零，比关闭钻头少用 9.541667 秒及 331.779519 J。但同船绕行只慢 0.05 秒，保持 100% 完整度且少用 236.151518 J。本轮未证明值得推荐的独立整关钻头策略，不继续搜装配、改路径或改参数，不合入生产、不新增玩家包。

关闭钻头的直进样本也成功；它在碰撞作用下逐渐绕过仍存活的上方浮石。这里的“同路径”指相同预设航点和控制器，不是强行令物理轨迹相同。

- 三样本均使用完整相同船和台；绕行仍携带并计入钻头，没有偷偷改用更便宜或更强的船。
- 钻头按住 1.55 秒，用能 93 J；9.966667 秒首次切石，11.333333 秒上石归零。上石另外 2.329850 HP 损失来自原有碰撞，不能计成钻伤。
- 两个迎石样本均在 9.966667 秒首次接触时损失相同 4.414067 HP 货物完整度，来源为 cargo_contact_impulse。钻头不免冲量。
- 开钻/关钻直进的盾实际吸收分别 2.524004/2.693429 HP，耗能 3.786006/4.040083 J；绕行均为零。本轮没有盾关或缓冲关的额外样本，不能声称已单独测量它们的贡献。
- 所有船件存活并回收，丢失/耗用费用为零。预核费用使用已有 Chapter.quote：开钻 15 能费 + 19 货损 + 1 维修 = 35；关钻直进 23 + 19 + 1 = 43；绕行仅 9 能费。这不是正式接单、结算账单或原生 GUI 试玩，未动库存、余额、存档或章节。
- 0.05 秒脚本时间差不能视为有意义的玩家收益。未测试更便宜的绕行装配，也不声称钻头在所有关卡永远无用。

## 冻结与失败保留

DESIGN-FROZEN.json 在任何 configure/release/step 前写入，SHA256 `24239cdcab111a63ec7a90d245af5d3c2cbdafcf59e7050ef305805551babd68`，运行后未变。首次 harness 尝试在台蓝图 JSON 数字拼写比较处主动退出，尚未 configure 或运行物理；原失败与脚本仅留本地。只将比较修成递归数值/结构精确相等，未修改冻结装配、输入策略或游戏参数。随后恰好三个物理样本各运行一次，退出 0、最终日志无错误或警告。

## 最小可移植研究源码

只保存本 README、compare.gd 和 DESIGN-FROZEN.json。逐 tick 输入、全状态轨迹、原始结果 JSON、日志和隔离用户目录只留本地，不进入源码备份。无需 run.py，不需要生产源码覆盖或重新封包。

以下仅供另行获准后的复现，不是继续运行本轮实验的指令：

1. 从已经备份的 dev33 玩家候选或恢复配方取出 StarCourier.pck，核对上述 SHA256。
2. 使用 Godot 4.6.3。将三个研究文件复制到独立可写实验目录；不要在正式源码目录运行，因为脚本会将研究结果写到自身所在目录。
3. 把 PACK 指向核验后的 PCK，EXPERIMENT 指向该独立目录，GODOT 指向 Godot 4.6.3 可执行文件。先创建隔离目录，再运行：

```sh
mkdir -p "$EXPERIMENT/isolated/home" "$EXPERIMENT/isolated/data" "$EXPERIMENT/isolated/config" "$EXPERIMENT/isolated/cache" "$EXPERIMENT/isolated/runtime"
chmod 700 "$EXPERIMENT/isolated/runtime"
HOME="$EXPERIMENT/isolated/home" \
XDG_DATA_HOME="$EXPERIMENT/isolated/data" \
XDG_CONFIG_HOME="$EXPERIMENT/isolated/config" \
XDG_CACHE_HOME="$EXPERIMENT/isolated/cache" \
XDG_RUNTIME_DIR="$EXPERIMENT/isolated/runtime" \
"$GODOT" --headless --main-pack "$PACK" --script "$EXPERIMENT/compare.gd"
```

脚本直接加载 PCK 内的实际 profile/solver，读取同目录冻结 JSON，经正常 configure → release_launcher → set_free_flight_input/step 执行三样本。反馈控制器会按真实状态产生不同输入，这是钻头导致世界状态变化后的正常结果。它不修改生产项目、PCK 或游戏参数。
