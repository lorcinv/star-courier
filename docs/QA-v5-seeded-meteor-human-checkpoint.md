## 候选包含什么

1. 种子 v1 的新委托选择与完整航线快照。内容只在保存的委托边界选择，既有种子、物理 / 输入协议和三个冻结的 v1 作者辅助文件不被重解释。
2. 有限轨道流星的作者规则、委托接入、可见提示、实际碰撞 / 钻切 / 护盾反馈和有限碎片。它仍是运动学定轨障碍，不是能被撞偏的自由刚体。
3. 普通走廊的必要内缘 / HUD 安全区构图与目的地文字。进入距收件处 60 m 以内才出现普通航段的接近提示；不修改碰撞、收件或结算条件。
4. 栅格手机外壳、跨版本重放种子 / 评价账本完整性校验。未知未来客户保留原始身份；共享中性投影仅用于评价显示。无效在途协议在创建世界、HUD、输入所有者或求解器之前进入恢复提示，原存档保留。
5. 人类客户的注册部件、头部与完整姿态覆盖，以及手部—同一包裹—机器人支撑衔接。另三类客人、店员源图 / 动作、故事、经济和实际移交锚点保持原有边界。

## 失败与修正记录

早期失败均保留，没有用较窄通过覆盖它们：

- 第一轮：流星字段验证将 bool / Array / Dictionary 与字符串直接比较，Moon 套件虽然报告已通过断言，仍产生 15 条引擎错误。修正为递归、类型安全的 JSON 比较；已知保留事件字段必须验证。214 个嵌套字段的永久变异套件包含 11,116 项检查，拒绝的副本保持原字节；十条有效作者航线序列化摘要不变。
- 第二轮：旧地面 HUD 夹具在仅推进到 150/360 m 时就期待“接近收件”文字，与明确的 60 m 阈值冲突。先保留远距离不显示提示的断言，再将接近夹具移到 310/360 m；没有为通过测试放宽运行时规则。
- 第三轮及独立诊断：旧恢复夹具在强制早期阻断后仍解引用不存在的世界，并期待较晚的恢复标志。夹具改为验证更强的早期边界，同时保留原存档、财务、时间线与阻断行为断言。
- 第四轮：旧货物姿态夹具与未检查的流星测试输出路径导致失败 / 挂起，见本文开头。独立套件收集机制会保留进程失败和引擎诊断；06 已补上逐套超时，防止错误后不退出的场景树无限占用验证窗口；并验证挂起、零退出码引擎错误、非零退出码均被拒绝且后续独立套件继续执行。
