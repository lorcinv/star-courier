# v5 店内走跑与共享输入检查点

2026-10-10。开发中版本；本记录不表示最终人物、美术、实体手柄或 Windows 性能验收。

## 冻结实现

- 店员由实际 A/D 或共享摇杆输入沿可达地面移动，0.5 秒同向保持后平滑跑步。转向、制动、柜台前后层、机器人占地、扩建边界、回前台与附近交互均由实际位置判断。
- 走、跑各有 32 张派生栅格采样；生成原图、身体部件变换脚本和来源说明完整保留。跑步有独立前倾造型及离地期，不是加速播放走路。不是 Spine。
- 输入上下文覆盖店内、菜单、装配格、对话、装货、模态框与飞行。按键释放、摇杆归零、失焦、断开及焦点切换有明确屏障。真正的手柄导航所有权与提示文字的防抖分离。
- 四类客户仍为旧的稀疏姿势循环；更平顺的客户步态在独立素材分支准备，不包含在这个候选中。

详见 [动作来源与限制](actor-locomotion-v2.md)、[店内通路](shop-locomotion.md)、[输入映射](controller-input.md)。

## 候选打包边界

候选的独立源码备份保留生成原图、栅格注册 / 动作脚本、历史 Blender 与 REAPER 工程。可执行包显式排除历史 3D 显示层、QA / 工具 / 缓存 / 原画，保留实际动态加载素材清单和许可证。Godot4.6.3 小型实验证实 all_resources 本身包含 JSON；显式包含清单用于可审计意图，并非修复一个已确认丢失的文件。

导出成功不等于运行成功。必须检查实际嵌入 PCK 的每项完整性、清单引用、许可和排除项，再单独记录本地 Windows 启动 / 输入 / 性能结果。
