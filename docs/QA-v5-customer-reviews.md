# 次日客户留言：保存基础与界面验收

更新：2026-10-10。保存 / 结算基础和店内客户留言界面现已接入。独立候选和合并工作树均通过真实窗口验证；合并后的 81 个 Godot 套件聚合已通过。

## 发布规则

按用户明确要求，正式配送结算时只保存事实，下一营业日才出现前一天的客户留言。免费试飞、未发货取消和未接委托不产生评价。正式失败可以收到对应留言。留言不重复支付运费、不修改声誉，也不捏造尚未实现的鸟类伤害。

- 正式结算的财务、故事进度和待发布事实共同保存。磁盘写入失败或事实校验失败，三者一起回滚；画面停留在已结束的飞行并等待重试，不显示未入账回执。
- 下一天的日历、订单、故事和留言共同保存。保存失败回到原来的夜间状态，不能先发布未来留言。
- 当日配送回执保留收入、成本和真实结果；旧版即时“客户回信”不再在当日报告中显示。
- 最多保存当日两条待发布事实和最近三十条已发布留言。重复回调、重启和旧结算 ID 不会再次发布。

## 存档兼容

全局存档版本仍为 5，客户留言有独立的版本字段。真正的旧存档从当前日期初始化空留言，不依据过去账本伪造历史评价。已存在但损坏的留言记录不能被当成“旧版缺字段”；优先读取有效备份，否则保留原文件并停止保存及经营操作。

同一存档的设置中保留兼容标记，可以识别已验证的旧 v5 写入器丢失新字段的情况。**不支持任意降级写入。** 如果其他程序同时删除记录和兼容标记，就无法把这种损失与真正的旧存档区分；回退前应保留完整备份。

## 界面与复现

店内「客户留言」显式打开面板，装货、对话、飞行和其他模态界面不能抢占。打开时店员保持位置 / 比例 / 朝向并拿起已有平板；关闭后空手，已按住的方向和确认键必须松开后再按。客户留言拥有独立焦点上下文，Escape / 手柄返回只关闭该面板。没有自动弹窗或再次发放奖励。

原生复现工具为 `tools/qa_customer_review_phone_native.py`，配合 `tools/customer_review_phone_seed.gd` 和只读 `tools/customer_review_phone_observer.gd`。必须使用独立测试项目、全新输出目录及专用 Xorg 显示；脚本会为测试创建隔离的 XDG 保存目录。`--approved` 是 GPU 测试协调门槛，不是用户授权替代。测试不会连接用户桌面。

当前平板是完整栅格姿势，其两只鞋与空手待机的绘制位置并非完全相同。本轮验证根节点 / 比例 / 深度和输入连续性；不能据此宣称逐脚无缝过渡。店员 v4 刚性栅格动作已合并，并通过同一原生窗口流程复核。其衣服 / 头部注册保持一致，但整幅平板与分段步态仍是明确的绘制边界。
