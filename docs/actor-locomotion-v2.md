# 店员行走与跑步：纯 2D 栅格动画

2026-10-10。本轮仅升级直接操作的店员。平板读单、点击、确认动作保持原清单数据；四类客人沿用已有四张画、六个节拍，没有把它们称作已完成的新绑定。

## 实际改动

- 两份内置 imagegen 原图分别提供直立步行、前倾跑步造型。角色身份来自已有店员平板原图。原始 PNG 均保留在 `source_art/2d_v5/actors/locomotion_v2/`。
- 新图的八格草稿仍有重复领先腿的问题，所以没有直接将草稿的八个标签当成正确步态。最终从原图分出完整头身、袖子、近远侧大腿、小腿与鞋，使用各自实测关节进行二维栅格部件旋转与叠放。头脸不变形，没有代码画出的身体补片，没有 SVG、3D 或 Spine 文件。
- 每种步态有 32 张不同的组装采样图。它们是生成画稿的栅格部件变换结果，并非 32 张单独由 imagegen 绘制的新原画。近远侧腿按半周期交替，手臂有相反方向的摆动。
- 行走有接触、压低、过脚、抬升节拍，始终至少一只脚支撑。跑步使用不同的前倾身形、回收轨迹和较短支撑期；32 张里有 8 张双脚离地，离地采样占 25%。跑步不是把行走加速。
- 周期长度以 240 像素参考身高计，走路约 135.385 像素，跑步约 213.333 像素；在实际 210 像素显示高度下分别约 118.462 和 186.667 像素。相位只来自控制器实际累计位移。
- 相邻采样之间，只对髋部以下的栅格采样做小幅水平补偿，使支撑鞋与控制器位移相抵消。头、髋部、角色节点位置不因此平移。当前两类步态的补偿量均限制在有限采样步幅内。
- 停止使用原有站立图；明确记录原站立图朝左，左右停步都按所需方向注册。恢复原图、平板动作和离地阶段清除支撑材质。转身就地重新选择支撑，不持有旧方向的世界锁定点。

## 资源与 API

`ActorMotion2D` 增加 `apply_run(distance_px, facing_right)`、`run_cycle_distance()` 和 `apply_idle(facing_right)`。原有 `apply_walk`、辅助动作、恢复原图、WeakRef 目标、隐藏冻结、RNG 隔离以及饰品髋部挂点继续保留。

每个适配器不新建任何节点；最多复用一个着色材质。角色绑定时预热清单里的有限图集文件，移动时不再逐格读取 PNG。固定缓存上限为 112；当前五种角色的动作清单合计 87 张 PNG（店员 64 张步态采样、3 张平板动作，客人 16 张行走、4 张告别）。支撑补偿直接采样当前纹理，不载入额外遮罩纹理。

## 验证

- `tests/test_actor_motion_2d.gd`：1157 项通过。保留原有真实资源、镜像、饰品、缓存、隐藏、非法数据及弱引用测试。
- `tests/test_actor_locomotion_2d.gd`：2612 项通过。含两种步态、两个方向、实际位移支撑锁定、跑步离地比例、停步方向、平板恢复、隐藏冻结、1600 次模式切换缓存平台及零新增节点。
- `tools/test_actor_motion_assets.py`：1080 项通过。检查原图 SHA、派生 PNG、统一调色板、二值透明度、注册、实际离地及不同采样。
- 支撑锚点的两周期实际位移测试中，最坏世界坐标误差约 0.000031 像素。这个数是坐标契约，不是渲染器的亚像素画质宣称。原生录像逐帧检查中，固定地面刻度旁的支撑鞋边缘仍有约 1–2 像素的最近邻取样/编码抖动。
- `tools/actor_locomotion_study.gd` 与 `tools/capture_actor_locomotion_study.py` 使用真实进程时钟，以游戏实际 210 像素高度、155/300 像素每秒对比行走、跑步、停止和反向。采集 30fps 不是引擎帧率宣称；没有 fixed-fps、手动步进或视频加速。

第一版隔离循环位于 `docs/qa/v5/locomotion-v2-native/`；其初次录制早于缓存预热和站立原图朝向修正，应按 `capture-metadata.json` 的源码 SHA 判断版本。`docs/qa/v5/shop-locomotion-route/` 的修正版路线录制由程序输入驱动，也不能冒称操作系统真实按键录像。真正的原生输入验收另由主测试记录提供。

本轮仍有可继续美术打磨之处：某些关节折角较硬，后续可用匹配的手绘弯曲关节补画改善。这不改变支撑鞋锁定、双腿交替、独立跑步和真实离地的行为。

## 参考与重建

借鉴的是 [Motion Twin / Thomas Vasseur 关于《Dead Cells》动画制作的第一手说明](https://www.gamedeveloper.com/production/art-design-deep-dive-using-a-3d-pipeline-for-2d-animation-in-i-dead-cells-i-) 中先读清关键姿势与节奏的原则，没有复制游戏角色、动作素材或其 3D 管线。

先运行 `source_art/2d_v5/actors/locomotion_v2/build_raster_rig.py`，检查整圈采样与关节连接，再运行同目录的 `register_runtime.py`。后者只更新店员行走/跑步字段，并断言既有平板数据不变。不得用旧版 `prepare_clerk_motion.py` 覆盖当前清单。
