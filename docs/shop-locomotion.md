# 店内直接移动

2026-10-10。本轮仅接入店员的自由移动、柜台接近与原有工位 / 补给入口，不实现店铺装修或新的可调查物件。

## 手感与输入边界

- `CourierInput` 负责 A/D、手柄横轴与可调死区。移动层只使用 0.001 的数值阈值，不再叠加第二层手柄死区。
- 走路速度为 155 世界像素/秒。相同方向保持 0.50 秒后，速度平滑升到 300；手柄需要至少 0.85 的有效推量才积累跑步保持时间。轻推维持按推量缩放的走路。
- 加速 900、松开刹车 1250、反向刹车 1650 世界像素/秒²。反向时先减速，实际速度换向后才改变面向。撞到边界或被挡住会清除跑步保持时间。
- 累计实际路径距离驱动画格。停止时不增加距离；不做整个人上下浮动、残影混合或把同一套走路画加速冒充跑步。跑步仅调用独立的 `apply_run`。
- 内部以不超过 1/120 秒的小步积分，同一活动帧最多处理 0.1 秒。大卡顿不会补走过去的墙钟时间。
- 进入模态界面、失焦、隐藏、装货或飞行会清除直接输入和保持时间。恢复后需要回到零输入，再产生新的方向输入。柜台故事所需的自动回程独立于直接输入。

## 地面与通路

直接移动只走原画已有的甲板，不落到下方管线。柜台后脚底为 y486，柜台右端 x452 处连接到 y496 的甲板前沿，然后可以继续向右走。该 10 像素深度来自画面约 y466–500 的浅透视地面；机器人仍停在原来的 y486。

柜台后的脚保持被前景柜台遮挡；绕到实际右端后才进入前景遮挡层。前后走道用浅透视脚底占地判断，机器人水平间距 58 像素、投影深度间距 8 像素。机器人如果暂时占住转角，会阻挡进入，仍允许店员退后。不会更改机器人位置来让路。飞行器所有合法工位格都在这条前沿走道上方。

基础工坊右边界为 x864，在从 x965 开始的发射架前为完整伸出的鞋子保留 101 像素。扩建后的边界为实际车间出口向内 96 像素。自由移动及从手动位置自动回程时，相机以 1.0 的世界倍率跟随实际店员，保留像素对齐；编辑器自己的平移与缩放独立保存。

装货结束后的店员可能站在工位 y486。开始自由移动时会用一个真实的 10 像素连接步进入前沿，不瞬移。点击柜台时沿同一通路返回精确的 (276,486)，到达后才发送可打开柜台的信号。普通重绘、切换页面或订单数据刷新都不能把自由移动中的店员拉回柜台。

## 接口

- `world.set_shop_input(axis, enabled)`：主控制器每帧传入已处理死区的横轴和当前上下文。
- `world.shop_interaction()`：返回附近原有入口的 id、短标签、是否可用和路径距离。柜台、工位和夜间补给各自有有限范围。
- `world.is_at_shop_counter()`：与当前页面无关，验证店员确实在柜台接待点，供接单守卫使用。
- `world.request_shop_navigation(action_id)`：已经到位时返回 true，否则开始物理行走。到达后发出 `shop_navigation_arrived(action_id)`。
- `world.cancel_shop_navigation()`：取消尚未完成的点击寻路。
- `world.shop_locomotion_snapshot()`：只读测试状态。移动模块不改变订单、包裹、库存、经济或飞行物理。

## 验证范围

- `tests/test_shop_locomotion_2d.gd`：31 项通过。走 / 跑阈值、轻推、加减速、反向、停止冻结、失焦式输入锁、转角、机器人占地、普通与扩建边界、连续连接步、寻路、30/60/120 Hz 距离一致性及无效数据。
- `tests/test_shop_locomotion_world.gd`：31 项通过。实际世界脚底 / 遮挡、柜台接近、点击到达、模态与页面切换、隐藏 / 飞行返回、普通重绘、两档扩建、相机及包裹身份。
- 原 `test_cargo_transport_2d.gd` 的 229 项仍通过，覆盖共同装货、跳过、取消、新订单、隐藏、失焦、重启表现与资源平台。
- `docs/qa/v5/shop-locomotion-floor/` 是原生 Godot 渲染器中的地面构图夹具，明确不代表原生键盘 / 手柄输入或步态最终验收。

独立跑步和面向正确的站立图像已通过实际世界检查。`tests/capture_shop_route_study.py` 可复现不带 HUD 的正常速度路线片段，输出在 `docs/qa/v5/shop-locomotion-route/`。它使用真实进程时钟，包含短走、停止、保持跑步、反向及回柜台；不使用固定引擎帧率、手动推进场景时间或视频加速。源码哈希、实际运行时间及逐段状态另存。

这仍是渲染器中的程序化输入夹具，最终原生键盘 / 手柄回归由主验证流程单独记录。手柄模拟事件不等于真实硬件体验，画面录制帧率也不等于引擎性能，用户手感及美术验收仍是独立判断。
