# 虫洞与苔光驿站配送切片

2026-10-10。当前已接入主游戏的开发阶段；正式配送的原生键鼠 / 重启验证已通过，侧面入口的最终动态片段已完成独立画面复核。从全新店铺自然经营至第 3 天的解锁和正式交付，现已另外通过 84 项原生键鼠检查。本页不表示最终美术或完整游戏验收。

## 玩家流程

新店先做地面屋顶订单，再按原声誉条件开放升空订单。声誉达到 7 后，新生成的虫洞订单会要求先穿云升空，对准晨星虫洞，再驶向有独立紫色浮岛背景和珊瑚色收件设备的苔光驿站。常规完整送达的进度下，第 3 天的重货订单可以提供这一航线。已经接下、在途或已结算的旧订单不换成新路线。

起点仍是店铺右侧的实体发射台，装置、货舱与发射准备沿用当前连续流程。虫洞口不是自动过场按钮：玩家必须驾驶整个真实连接组件通过入口，并在出口继续驾驶和避障。大型装置、分离、实际货物质量、推进方向、能源和碰撞仍参与计算。

## 规则与成本

- 新物理 / 输入版本为 `pilot-v4-wormhole`，内容标记为 `wormhole-otherworld-v1`。旧 v1/v2/v3 模拟器源码保持原样，存档按原版本恢复。
- 当前压缩航段中入口位于 `(600, -150)`，出口位于 `(1000, -150)`，收件台位于 `(1240, -150)`。跳过的坐标段由真实传送事件完成，不靠横向坐标切换背景。这些是关卡计量，不代表现实天体距离。
- 洞口半径 13 m，保守边距 0.125 m。当前组件的质量加权外接轮廓，包括钻头接触端，必须全部容纳。预检按真实结构图显示口径和轮廓；不是限制推进器数量的全局禁令。
- 入口与普通碰撞都进入按时间先后处理的扫掠事件。同刻碰撞优先；过洞不会抹掉已发生的撞击。
- 出口按完整组件外接轮廓检查边界、实体障碍和其他组件，保守预看 0.22 s。堵塞或储能不足时不进行跳跃。传送后没有通用无敌或额外制动。
- 驿站具有 2000 J 的有限通行储能。每次实际过洞组件消耗 `25 + 2 × 组件质量(kg)` J。保持飞船本身速度、角速度、耐久、质量和电池余能；驿站消耗只计入一次能源成本。
- 分离组件独立检查和收费；零件保存已经过洞的来源标记，结构重建、分裂或重启不会重复收费。
- 正式结算依旧只有一张唯一账单。报告中的“其中虫洞通行”是总耗能的子项，不是第二次扣款。试飞只显示预计收益。
- 当前入口 / 出口上、下端具有真实碰撞硬件。异世界直线上的矿块可绕行，也可由正确供能、合适接触速度的钻头处理；不能靠虫洞删除后续碰撞。装甲和护盾仍按其有限规则工作。

## 持久性与表现

主控制器使用相同的正式 / 试飞配置、种子、60 Hz 稀疏输入和 120 Hz 物理步长。入口前后各一侧的 JSON 存盘重启，检查完整物理状态、接触缓存、事件、通行标记与驿站余能。恢复时默认暂停，清除旧输入，不重放点火或传送亮效。无效或不支持的版本保留原记录并停止恢复，不能偷偷按其他规则继续。

背景只认实际货舱的过洞来源状态；先过去的脱离零件或单纯越过出口 X 不能切换场景。入口到出口的相机同帧切换，避免横扫不存在的中间空间。背景保持同方向普通环绕与相机视差；近景装饰弱化色彩和透明度，没有碰撞。模糊仅作用背景，暂停、关闭模糊和减少动态都可以立即清除。

生成式原图、透明边缘处理、像素清理和精确注册保留在 `source_art/2d_v5/wormhole/` 与 `source_art/2d_v5/otherworld/`。收件设备以实际空腔而非图片外框对齐触发区域。成功镜头保留空腔、顶棚、后壁与甲板。初版正面环图在横向飞行时会产生穿过实心边框的错觉，现已替换成独立顶 / 底硬件和侧面能量入口。硬件逐个注册到实际障碍中心和半径，细护圈标示真实碰撞边界；只有能量图层在实际穿越后短暂增强，恢复与减少动态不播放该效果。旧正面环诊断截图不能代表当前入口。
