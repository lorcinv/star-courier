# 星际快递：动作修正与重复游玩扩展

更新：2026-10-11。这是新增工作的分阶段验收表，不是已完成功能表。继续云端开发；先保存当前路线与经营检查点，再扩展。现有单一店内步态、平板核单和纯 2D 生成式栅格美术继续使用。

## 1. 先修人物

- 头脸不再只是静止贴图：在统一头 / 颈注册和头部尺寸下，加入克制的眨眼、视线与小幅转头。需要的新表情和部件来自图像生成，不能放大 / 缩小整颗头制造动作。
- 修正髋、膝、外套与鞋的遮挡。远腿在后、近腿在前，骨节要有被上层衣物覆盖的余量，不能出现分离边、双重黑线或不合理交叉。
- 以实际位移驱动支撑脚与摆腿，起步、移动、惯性停下、停止之间保持连贯。店内不恢复奔跑；飞行全功率推进保持原义。
- 验收：同一镜头下检查左右往返、停稳、交谈和平板切换的原速片段，并复核脚底与地砖的相对位置。元数据和帧数不能代替实际画面。
- 参考官方 Godot Skeleton2D / cutout 工作方式；先做项目内的局部修正，不因参考而换回 3D，不把现有栅格层级称为 Spine。

当前进度：店员刚性栅格动作已有独立片段及后续 85 套件检查点。本轮继续接入人类客户的注册部件、手部—包裹—机器人支撑衔接。原速片段 05 已通过有界独立画面复核；之后的减少动态结算与取消订单修正通过 544 项定向检查，不能沿用原片段结论。另一项动作兼容套件通过 1,165 项。新包已通过 103 套件合并冻结回归；另外三类客人和实体手柄仍未获得本轮原生步态验收。详见 [本轮检查点](QA-v5-seeded-meteor-human-checkpoint.md) 与 [店员动作修正](QA-v5-rigid-clerk.md)。

## 2. 次日手机评价

用户明确修正了时间：前一天配送结算后，**下一天刷新客户评价**。

- 唯一正式结算先保存待发布事实：订单 ID、配送日、客户身份、目的地、成功 / 失败、时效、完整度，以及将来真正实现的事件归因。
- 成功进入下一营业日时，只发布此前未发布的上一日评价。记录配送日和发布时间；关闭 / 重启、重复按钮、重复结算不能复制评价。
- 免费试飞没有评价；未发货就取消的委托不伪造配送评价。正式失败可以收到相应评价。现有配送回执与短结果对话保留，不冒充次日评价。
- 手机显示简短、与事实一致的原创新评价。打开时复用持平板动作；关闭后恢复正常人物和输入，不影响订单、装货或货物位置。
- 不预先显示当前配送的未来评价，不重新结算钱款或重复发放声誉。保护鸟类只使用实际、可归因的首次伤害事实，不捏造生态原因或自动扣款。
- 验收：多订单、失败、试飞、取消、隔日重启、存储失败、重复下一天和有限历史容量；真实 UI 检查手机开关、角色姿势与键鼠 / 手柄焦点。

当前进度：次日发布、唯一账本与生成式手机外壳已集成。本轮进一步接入正式保护鸟委托的伤害事实；试飞、背景鸟与无关来源不产生生态差评。冻结回归通过。独立 QA 第 5 天受伤委托到第 6 天 2/5 留言的片段已有有界复核；另从真实赚得的第 4 天存档完成安全保护鸟 / 普通两单，第 6 天无当日结果，第 7/8 天各增加一条前日 5/5 留言，重启无重复。两组证据和资格分别保留，不混作同一次自然全流程。

## 3. 有种子的路线与委托变化

- 先做有限的作者片段组合：路线形状、障碍、任务要求和短对话模板分别变换，而不是无约束散布障碍。
- 每份新委托保存生成版本、种子和已实现的完整航线。已接、在途和已结算的旧航线继续使用原快照，不在读档时重新抽取。
- 私有生成器不消耗运行中的物理随机序列。相同保存内容 / 输入必须重现同样事件、成本和结果；需要新运动 / 碰撞规则时使用新协议版本。
- 生成约束包括真实整船口径、出生 / 出口净空、可见预告、可穿越的路线走廊和普通初始船的能量预算。强力或不平衡改装仍承担真实代价，不靠隐形推力补偿。
- 对话采用与 NPC、委托和结果对应的原创片段 / 语法，不需要付费的运行时大模型。
- 验收：固定种子样本集、坏种子回退、存盘 / 恢复、试飞 / 正式一致性、实际多种路线片段与人为操控检查。自动引导成功只能证明一个可行输入序列。

当前进度：种子 v1 的 2,048 份委托、32 条可行输入航线、八次精确重放和真实赚得进度的键鼠检查保留。新的可读普通作者规则已通过初始船、16.95 kg 参考装置、适配器、旧订单及合并冻结回归；只作用于真正的新批次，已保存路线不变。1280 宽样本中船体约 60 像素，必要内缘保持预告；约 30 像素的后方余量、快速拉远及普通到站裁切仍是未完成的构图问题。追逐路线需要单独保留后方空间，不能无限缩小船来解决路线布局。

后续原创接单语句已按种族 / 航线准备了 32 个短片段及独立保存格式，当前仍在隔离验证，尚未进入本检查点。对话数据不能在读档时重抽，也不能改写已保存的发言。

## 4. 按生态逐个加入事件

每次只接入一种可辨认、可躲避、能记账的事件，完成真实片段和回归后再添加下一种。

- 太空：海盗 / 路线怪物与流星事件。武器、钻头、护盾与真实能源有各自作用；避免贴脸生成和无提示的不可避伤害。
- 主城低空：拥堵与警察追逐，使用真实移动障碍 / 追赶行为及清楚预告，不只换个背景名称。
- 精灵星球：有生命的藤蔓，以可读的准备 / 动作 / 恢复周期改变通路。
- 火山星球：有先兆的喷发与安全窗口，维持可达路线和有限特效开销。
- 生态良好星球：可辨认的保护鸟类。只有发生真正、可归因于玩家的伤害后才形成差评事实；靠近、避让、背景鸟或无关敌人行为不自动罚玩家。

新事件必须有独立归因、版本化保存和可重复测试。风险提示是玩法信息，不把开发备注或阶段解说放回主界面。

当前进度：有限轨道流星已进入主游戏，正式委托、保存恢复、预告和避让 / 碰撞 / 钻头 / 护盾对照有证据。保护鸟现也已集成独立 v5 物理协议、有限 HP / 质量、连续扫掠、射线 / 钻头来源和唯一首次伤害事实；提示在整船安全通过后退休，反向重新接近可再次出现。安全 / 受伤与次晨评价分别有实际输入画面，合并候选通过 127 次脚本测试和原生经营延续。鸟的画面仍小、伤害结果偏依赖文字，不是最终生态美术验收。海盗、主城拥堵 / 追逐、活藤和火山喷发仍未实现。
