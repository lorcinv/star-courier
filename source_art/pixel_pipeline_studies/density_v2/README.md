# 提高像素密度：第二轮对比

本轮根据“图二有点模糊了，可以提高像素密度的分辨率”的反馈，将清理图从 640×360 提高到 960×540 和 1280×720。两版都重新读取未修改的 1672×941 原图，没有放大上一版 640×360 的清理结果。

## 建议

本张参考图建议采用 **1280×720 的逻辑像素**。实际像素数为上一版的四倍，店员的眼睛、嘴形、发梢，以及飞船窗框和亮边保留得更完整。4K 预览用最近邻放大 3 倍，每个逻辑像素对应严格一致的 3×3 方格。

960×540 是中间方案，实际像素数是上一版的 2.25 倍，4K 预览每格 4×4。它保留的细节已明显多于 640×360，但同尺寸脸部对比仍以 1280×720 更接近原图。

三个清理版本共用之前的同一套 96 色，保留暖黄店面、冷蓝城市、珊瑚色挑染和青色眼睛。本轮只改变采样密度，避免把调色变化误认为清晰度变化；实际查看后，无需为了这次密度修改先增加到 128 或 192 色。

## 给用户看的图

- `像素密度对比_原图_640_960_1280.png`：1548×1265，中文标注。原图、640、960、1280 的脸部和飞船局部都是同一画面范围、同一显示尺寸；局部直接从 4K 展示画布裁取并以 1:1 放进对比图。
- `clean_96c_1280x720_4k_nearest3x.png`：建议版，3840×2160。
- `clean_96c_960x540_4k_nearest4x.png`：中等密度版，3840×2160。

实际逻辑分辨率文件分别是 `clean_96c_1280x720.png` 和 `clean_96c_960x540.png`，与 4K 展示文件分开保存。

## 验证与范围

输入校验值保持为 `bd9388bd6cb6784572cabd0eca876bb6fce9a6d7c538438128d22d8367242cae`。上一轮文件不修改、不替换。源图单元边界完整记录在两份 `source_cuts.json` 中。

`density_validation.json` 记录逻辑尺寸、固定调色板成员、源像素采样、3×/4× 方格、上一轮文件不变，以及完整重跑的确定性检查。没有下载、安装或执行新的 GitHub 程序；沿用前一轮有来源与 MIT 许可记录的项目内处理代码。

这轮是参考图清理，尚不代表游戏已切换渲染分辨率。运行时需要单独测试性能、阴影和运动：960×540 可在 1080p 整数放大 2 倍；1280×720 在 4K 可整数放大 3 倍，但在 1080p 若坚持整数缩放，需要 1 倍居中留边。已把此区别交给游戏集成负责人。

网格与调色板规则不会补出原图不存在的细节。最终资产仍需单独检查轮廓、动画和小字，概念图里的文字不能替代原生游戏 UI。
